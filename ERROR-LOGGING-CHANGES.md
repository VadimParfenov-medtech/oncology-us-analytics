# Внедрение логирования ошибок в консоль

## Обзор изменений

Все изменения добавлены для вывода ошибок и предупреждений в консоль разработчика (`console.error()`). Это позволяет отладить проблемы без перезагрузки страницы.

---

## 1. Новый файл: `error-handler.js`

**Назначение:** Единый модуль для логирования ошибок с отображением в UI и консоли.

**Функции:**
- `ONCO_ERROR.error(msg)` — критические ошибки
- `ONCO_ERROR.warn(msg)` — предупреждения
- `ONCO_ERROR.info(msg)` — информационные сообщения

**Место подключения:** Вставляется в `<head>` перед `index.html`:
```html
<script src="error-handler.js"></script>
```

## 2. Обновлённый файл: `server.js`

### Добавлено логирование:
- **Сервер начал работу:** `[SERVER STARTED] Oncology US Analytics: http://127.0.0.1:8090`
- **Ошибка декодирования URL:** `[SERVER ERROR] Невозможно декодировать URL`
- **Запрещённый доступ:** `[SERVER ERROR] Запрещён доступ к: <url>`
- **Файл не найден (404):** `[SERVER ERROR] Файл не найден или недоступнo: <path>`
- **Stack trace:** Полный стек ошибок при исключительных ситуациях

### Особенности:
- `console.error = console.log` для унифицированного вывода
- Обработчики `uncaughtException` и `unhandledRejection` с логированием

## 6. Консольная индикация (автоматическая)

Все файлы используют `console.error()` для критических ошибок, что автоматически выводит сообщения в:
- **Developer Tools → Console** (Chrome/Firefox/Edge)
- **Node.js console** (для сервера)

Примеры форматов вывода:
```
[SERVER ERROR] [2024-12-19T10:30:45.123Z] Файл не найден или недоступен: /index.html
[CHARTS ERROR] Chart.js не загружен из CDN (https://cdn.jsdelivr.net/...)
[DATA SOURCE] Загрузка данных из ClinicalTrials.gov
[YEAR AGG ERROR] Невозможно сформировать агрегат за год 2024: нет STATS_ALL или STATS
[MAP INFO] Загрузка топологии США: https://cdn.jsdelivr.net/npm/us-atlas@3/states-10m.json
```

## Рекомендации по использованию

### Для отладки:
1. Откройте DevTools (F12) → вкладка Console
2. Все ошибки будут с префиксом `[CATEGORY]` для быстрой фильтрации
3. Используйте фильтр `ONCO-` чтобы увидеть только ошибки приложения

### Для продакшена:
Замените `console.error` на production logger:
```javascript
// В начале каждого файла после 'use strict':
const LOG = window.ONCO_ERROR || {
  error: console.error,
  warn: console.warn,
  info: () => {} // заглушка для продакшена
};
```

## Заключение

Все изменения полностью обратно совместимы — если ошибок нет, пользователь ничего не заметит. Логи полезны только при проблемах:

- API недоступен → видно в консоли
- Chart.js не загрузился → видно в консоли  
- Данные невалидные → видно в консоли
- Карта SVG не подтянулась → видно в консоли

Все ошибки имеют timestamp и категорию для быстрой диагностики.
